# SuperDoc Document API: reproductions from a 1.x → 2.x migration

Runnable, self-contained reproductions of the Document API behaviours we hit while moving a contract
platform from SuperDoc 1.45 to 2.x. Every case opens a `.docx`, makes the exact calls we make in
production, saves, and decides the verdict from the **exported package XML**, never from "the call did
not throw".

- **[TICKETS.md](TICKETS.md)**: the findings grouped by root cause, with what we need and why. Start here.
- **[RESULTS.md](RESULTS.md)**: every case × every SDK version × platform, regenerated by `run-all.mjs`.
- **[QUESTIONS.md](QUESTIONS.md)**: items that are questions or confirmations, not reproducible bugs.
- `cases/<id>/README.md`: context, steps, expected, actual, "done when" and the question, per case.

## Run it (5 minutes)

Requirements: Node 22+ (we use 24.19.0), npm. Linux, macOS or Windows.

```bash
npm run setup                                  # jszip + the three pinned SDK versions (npm ci each)
node cases/T01a-create-after-break-deletes-siblings/repro.mjs 2.15.0   # one case, one SDK
node run-all.mjs                               # every case × every installed SDK, writes RESULTS.md
node run-all.mjs --case T06 --sdk 2.16.0-next.17
npm run linux                                  # the same matrix in Docker (node:24-bookworm, linux-x64)
```

Each case prints its steps, the receipts, the relevant exported XML, then:

| Output | Exit code | Meaning |
| --- | --- | --- |
| `BUG REPRODUCED` | 0 | the behaviour described in the case README happened |
| `FIXED?` | 1 | the expected behaviour happened instead: please tell us which release fixed it |
| `ERROR` | 2 | the script could not complete (setup problem, host did not start); never counts as fixed |

Windows notes: keep the checkout on a short path (the SDK host binary fails to spawn past 260
characters with `HOST_DISCONNECTED … ENOENT`). On our Windows machine the `@superdoc/sdk-windows-x64@2.13.0`
host binary is refused by local security policy ("Permission denied" / `spawn UNKNOWN`), while 2.15.0 and
2.16.0-next.17 run; we therefore run 2.13.0 on Linux only. You may not see this on your machines.

Each `sdk/<version>/package.json` pins one exact version and its lockfile records the platform binary
for every platform. No ranges, no `latest`.

## How we use SuperDoc (so you can judge which fix unblocks what)

We generate, fill, review and sign construction contracts. Templates arrive as `.docx` files authored
in Word or Google Docs, often exported by SuperDoc 1.45 in the past. Four flows touch the Document API:

1. **Template import (browser editor).** A user uploads a template containing legacy placeholders such
   as `{{project_name}}`, `[buyer_initials]`, sometimes 100+ in one paragraph separated by line breaks.
   We convert each placeholder into an inline content control (`tag` = the field code) so every later
   fill is structural. Cases T01, T02a, T04, T07a.
2. **Server-side fill (headless SDK on AWS Lambda, linux-arm64).** Given merge values, we open the
   template by path, set every control's value, fill header/footer values, render tables, flatten the
   controls and save. Cases T02b, T03, T07b, T08a.
3. **Two-party signing (browser editor).** Signatures and initials are images placed inside block or
   inline content controls; each signer may only touch their own fields. Cases T05, T06, T08b.
4. **Review / redlines (browser editor).** Tracked changes with identities we persist, accept/reject,
   undo. Case T09.

The calls, as we make them:

```js
// headless (fill service)
const client = new SuperDocClient()
await client.connect()
const doc = await client.open({ doc: '/tmp/in.docx' })
// … contentControls.selectByTag / text.setValue / replace / create.table …
await doc.save({ out: '/tmp/out.docx', force: true })
await doc.close({ discard: true }); await client.dispose()

// browser (editor)
new SuperDoc({
  selector: container, document: file, documentMode: 'editing',
  user: { name, email }, disableContextMenu: true,
  modules: { comments: false, slashMenu: false },
  onReady: () => { const doc = superdoc.activeEditor.doc /* Document API */ },
})
```

## Fixtures

- `cases/<id>/fixtures/`: synthetic packages built by `cases/<id>/build.mjs` (deterministic: rerunning
  the builder reproduces the committed bytes; `SHA256SUMS` next to them).
- `fixtures/sanitized/`: five real templates passed through `tools/sanitize.py`, which keeps every
  structure (paraIds, runs, SDTs, fields, sections, numbering, tracked changes) and replaces every word
  outside placeholder tokens. See [fixtures/sanitized/README.md](fixtures/sanitized/README.md).
